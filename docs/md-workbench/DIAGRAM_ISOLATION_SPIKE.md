# Synthetic diagram isolation spike (T04 experiment)

This opt-in fixture tests the native boundary before a draw.io runtime is introduced. It is **not T04 or T16 acceptance**, an editor, an image/XML validator, a safe Save implementation, or a draw.io integration. No original document is used. Normal preview, shipping capabilities and persistence are unchanged.

## Build and observe

```
pnpm tauri build --no-bundle --features diagram-isolation-spike
```

Launch the resulting binary with `--diagram-isolation-spike`. Both the nondefault compile feature and flag are required. Default builds do not compile/register the fixture protocols, launcher or receipt hook. The dedicated workflow `.github/workflows/mdw-diagram-isolation.yml` first builds the default binary and checks that the flag alone creates no fixture. It then builds the opt-in binary and runs `scripts/diagram-isolation/windows.mjs` against actual WebView2 on disposable hosted Windows 2022. CDP is injected only through the owned test process environment. No release configuration enables CDP.

The runner writes `report.json` even on observation failure, exits nonzero on failed required observations, records the binary and fixed asset SHA-256 hashes and actual origins, and uploads artifacts with `if: always()`. It kills only its own process tree. The invoke key remains in memory; session nonce, HTML and source text are not logged. `native-receipts.log` contains at most 32 native-denial receipts with constant command names.

Local checks: `node --test scripts/diagram-isolation/protocol.test.mjs scripts/diagram-isolation/native-receipts.test.mjs scripts/diagram-isolation/observation-profile.test.mjs` and `cargo test --manifest-path src-tauri/Cargo.toml --lib --features diagram-isolation-spike diagram_spike`.

## Native containment

The only fixture window uses a native random `diagram-spike-…` label. It is never registered as an editor and does not match `main` or `window-*` capability selectors. The global custom-command guard derives the actual caller identity and rejects it before command dispatch; the feature hook records that rejection, without changing the decision. Plugin ACL remains independent.

Two compiled-in schemes serve distinct fixed origins: wrapper `mdwdiagramhost` and child `mdwdiagramfixture`. Each handler checks actual protocol context WebView label, live session, GET, exact host/path, absence of query, and a fixed route/MIME allowlist. There is no file mapping, generic HTML/URL argument, redirect, external resource, CORS wildcard or grant API. HTML interpolation contains only native random hex and constant origins. Assets have `no-store`, `nosniff` and separate restrictive CSP headers.

The wrapper alone can frame the exact child origin. Both forbid network connections, images, fonts, workers, objects, base URLs and forms. Scripts are external self assets. The child iframe is cross-origin with only `allow-scripts allow-same-origin`; this does not change the ordinary preview's empty sandbox. Native navigation permits only the two fixed documents, popups and downloads are denied, and drag/drop is disabled. A denied navigation, host or child document reload, destruction, or a native 10-second asset deadline retires the fixture. JavaScript listeners retire after one exchange, on timeout or pagehide. Late messages cannot modify a completed candidate. The deadline bounds this experiment; it is not a host scheduler or resource reclamation proof.

## Synthetic protocol

JSON string envelope: `v`, `session` (native 128 random bits encoded as hex), `seq`, `kind`; only `load` and `candidate` additionally carry `text`. No XML/HTML interpretation occurs. Host expects `ready:0`, sends `load:1`, receives `candidate:2` or `cancel:2`. Child expects `load:1` or `cancel:1`. Unknown fields/types, invalid nonce, unexpected sequence, nonstring payload and malformed JSON retire the selected peer. Foreign source WindowProxy or origin is ignored before accessing/parsing data.

Limits: 64 KiB UTF-8 envelope with a cheap UTF-16 precheck, 32 KiB UTF-8 text, 32 accepted messages, 256 KiB cumulative accepted bytes per receiver, 10-second deadline. Fixed one-exchange output is much smaller. These checks run after browser message delivery; they do not prevent the browser allocating an adversarial structured-clone payload or prove separate OS processes. Nonce authenticates the session, not the honesty of code within it. Upstream draw.io does not promise this envelope/nonce; a future integration requires its own reviewed adapter.

## Evidence and deliberately unmeasured boundaries

Actual origins must be distinct, nonopaque, exact values in both `location.origin` and `MessageEvent.origin`. Windows is expected to use `http://mdwdiagramhost.localhost` / `http://mdwdiagramfixture.localhost`; macOS/Linux use custom URL shapes but might serialize opaque origins. A `null`, collapsed/equal or undeliverable exact target origin is unsupported, never accepted by nonce fallback, wildcard targetOrigin or a local HTTP server.

The [first Windows run](https://github.com/aharada54914/md-workbench/actions/runs/35010122177/job/104519696314) failed on WebView2 131.0.2903.86. Its artifact recorded the default-disabled check, distinct-origin roundtrip and parent-DOM denial, but only one native denial per custom command instead of the required two. The original observer did not attribute those receipts to wrapper versus child and stopped before the remaining checks. This is not a passing Windows result. Native unit compilation and pure Node tests do not establish native GUI behavior; macOS and Linux still need native observers. The fixture contains no draw.io bundle and makes no version, license, offline edit, compressed XML, rendering or resource-save claims.

The observer now sends wrapper and child probes sequentially and records their receipt-count deltas. A missing bridge or zero native receipts is `unsupported`, never a native rejection. An incomplete preceding observation prevents a later interval being accepted as an independently attributed pass. Unsupported custom IPC observations are retained while plugin/CSP/popup/reload checks continue; the default strict receipt profile still exits nonzero on any required unsupported or failed result. WebView2 uses separate [frame messaging events](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/frames#sending-and-receiving-messages); the Wry 0.55.1 used in that run registers only the top-level `WebMessageReceived` handler. Calling the child JavaScript bridge alone therefore cannot establish native receipt delivery. The attributed observer and genuine-frame observations were subsequently measured on Windows; their Node tests remain diagnostic logic coverage only.

### Fixed genuine-frame follow-up

Two additional observer modes (`--frame-roundtrip` and `--frame-active`) start separate owned native processes with `--diagram-isolation-frame-probe`. This opt-in mode uses the same host receiver and retirement handler. A fixed `mdwdiagramforeign` document first sends from the selected iframe's actual WindowProxy with a foreign origin; the same iframe then navigates to the normal child origin. A fixed sibling document sends from the expected child origin with a different WindowProxy. Both must be ignored before a valid roundtrip or the active-child rejection probe proceeds. Foreign/peer asset routes are denied outside this mode and still require the native protocol owner, exact allowlisted route and live deadline. The foreign document is served only once; reloading it retires the session.

The packaged observer first establishes a genuine main native control and four wrapper dispatch/rejection receipts, including a positive control for its wrapper bridge-call counter. It then observes child direct IPC and genuine child `parent.postMessage` calls during active and retired states. Active command-shaped input must be rejected by the protocol schema; retired input must leave the terminal state unchanged. The report retains the bounded observation duration, wrapper call count and native receipt deltas. Zero observed forwarding or native delivery proves only those paths within that interval; it is not an explicit native rejection or a claim that every IPC, filesystem or shell boundary is covered. No native iframe handler, command forwarder, permission or editor authority is added.

`tests/e2e/diagram-frame-provenance.test.ts` uses the fixed fixture sources with real Chromium frames to test origin/WindowProxy provenance, valid roundtrip and retirement. It does not simulate Tauri IPC and is not packaged WebView2 evidence. The separate Windows steps run after a successful feature build even when the earlier observation fails, and always preserve failures. Without an explicit measurement profile, missing child native-rejection receipts still produce `unsupported` and a nonzero exit in these modes; successful no-forwarding observations are stored independently. These observations do not change the authoritative requirement to keep filesystem/shell IPC inaccessible, nor establish full T04/T16 acceptance.

The default strict receipt profile requires the real roundtrip, cross-origin parent-DOM denial, actual native custom-IPC denial receipts from wrapper and child, plugin ACL rejection receipts, CSP connect/inline-script violations, popup denial and reload retirement. Missing transport, malformed-argument errors and CSP-blocked requests are not native IPC rejection receipts. The foreign-main protocol request may be blocked by main CSP before reaching native, or have its response hidden by CORS; this is recorded separately, with native unit ownership tests as unit evidence only.

The report's `passed_measured_subset` is deliberately narrower than complete boundary acceptance. Missing observations are retained in `missing`: native download callback receipt, all network vectors/socket capture, destroy/recreate, main protocol receipt when hidden by CSP/CORS, and macOS/Linux native runtime behavior. Popup page-count observation is not by itself the native denial callback receipt. Child plugin transport is not independently exercised by this first observer (top WebView ACL receipts are). Further native observers are required before issue completion. The strict CLI continues to fail on unsupported exact-origin or required-transport results. The explicit v2 measurement profile below changes only the narrowly identified child receipt expectation; it does not silently omit other observations.

Approved representation ADR2 is unchanged. T16's real offline runtime pin/inventory/license audit, upstream protocol adapter, edit/cancel lifecycle, XML/resource limits and security/save acceptance remain separate work.

## Explicit v2 Windows measurement profile

The CI measurement contract now explicitly selects `--observations-only` for the full synthetic observer and both genuine-frame modes. The default-disabled binary check remains required. This is a diagnostic scope revision, **not a product acceptance gate**. Approved SECURITY requires filesystem/shell IPC to be inaccessible and the protocol to validate source/origin/session/schema; it does not require an inaccessible child transport to dispatch a native command merely to emit a denial receipt. No native frame handler, forwarding bridge or capability was added.

```
node scripts/diagram-isolation/windows.mjs BINARY OUTPUT --observations-only
node scripts/diagram-isolation/windows.mjs BINARY OUTPUT --frame-roundtrip --observations-only
node scripts/diagram-isolation/windows.mjs BINARY OUTPUT --frame-active --observations-only
```

Omitting `--observations-only` preserves the strict receipt profile: the known missing child receipt is `unsupported` and exits nonzero. The previously recorded Windows unsupported results are not relabeled as successful v2 runs. A new v2 CI run is required. `--expect-disabled` still verifies that the default binary ignores the launch flag.

V2 records `profileVersion: 2`, the selected profile and mode, Windows/runner image, actual WebView2 engine version, exact Wry version/checksum/source plus Cargo.lock SHA-256, fixture and binary hashes. Its reviewed transport assumption is limited to registry Wry 0.55.1 on Windows. A different Wry version, registry source or package checksum fails this profile until separately reviewed. Engine changes remain visible in artifacts; changed delivery is a failure, not automatically another passing result.

The only exception is the child observation `bridge: sent`, `status: unsupported`, `reason: no_native_receipt` with exactly zero receipts for all four commands, measured duration, zero wrapper bridge forwarding, genuine main native control, and independently observed wrapper rejection receipts plus a working wrapper-counter positive control. Full observer records the child interval and final receipt delta; frame modes also record active/retired genuine parent-message observations. An unexpected native receipt, forwarding, unavailable transport, missing/failed control, incomplete checklist, observation error, premature owned-process exit or unconfirmed cleanup exits nonzero. The full observer still requires wrapper plugin ACL denial, CSP connect/inline-script rejection, popup observation and reload retirement; the workflow still runs both provenance modes. Unsupported origin is never exempt.

All required observations must finish before a bounded profile can return `passed_bounded_observations`. Its report keeps `nativeReceiptCoverage: unsupported` and `productAcceptance: unverified`; missing coverage is retained. Zero observed ingress/forwarding is evidence only for the measured paths and interval. It is neither a native denial receipt nor an all-transport filesystem/shell side-effect guarantee.

The actual frame cases cover selected WindowProxy with wrong origin, sibling WindowProxy with the expected origin, real exact-origin roundtrip, command-shaped schema rejection and retired-state immutability. Wrong nonce/session-generation and size/sequence/deadline negatives remain pure shared-receiver unit coverage (`sessionNegativeCoverage: unit_only`), not independently packaged negative observations. Real draw.io/offline editing, other operating systems and the remaining T04/T16 acceptance stay unverified.
